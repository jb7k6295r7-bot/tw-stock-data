# 內部人持股轉讓事前申報（全市場月彙總）2003-05～2026-09

⭐ 由 `build.py` 從 MOPS 舊站「內部人持股轉讓事前申報彙總表」建成；上市（sii）、上櫃（otc）、興櫃（rotc）三市場，**含已下市公司**。
依據：裁定 seq407。

## 來源

`POST https://mopsov.twse.com.tw/mops/web/ajax_t56sb21`
body：`step=1&TYPEK=<sii|otc|rotc>&year=<民國年>&smonth=MM&emonth=MM&sstep=1&firstin=true`

- 回 UTF-8 HTML 表格，一列 18 格，頁尾「總計：N筆」，不分頁；無資料回「無持股轉讓之情形」。
- 一發＝一市場×半年（同一民國年內）；頁尾總計 > 3000 或解析列數 ≠ 總計 ⇒ 程式自動改逐月重抓（本次沒有觸發）。
- 每發間隔 4 秒、失敗重試 3 次（間隔 30 秒）；遇驗證碼／「因為安全性考量」擋阻頁 ⇒ 立刻停（exit 3），不繞過。
- 原始回應可用 `--cache <資料夾>` 存在 repo 外，重跑時不再打官方。

## 檔與欄

`insider_predeclare_<西元年>.csv`（依申報日分年），UTF-8，一列＝官方一列申報。數字已去千分位轉整數；空白＝官方空白（⛔ 不是 0）。

| 欄 | 意義 |
|---|---|
| market | sii／otc／rotc（⭐ 申報當時所在市場：同一代號轉市場前後會分屬不同 market，共 822 個代號出現在 2 個以上市場） |
| declare_date | ⭐ 申報日期（西元 YYYY-MM-DD）＝**可用日** |
| stock_id, name | 公司代號、公司名稱（官方原字串） |
| role | 申報人身分原文（如 董事本人、經理人配偶、法人董事代表人本人、大股東本人、特定人本人…） |
| holder_key | ⭐ 申報人代碼＝`sha1("<stock_id>\|<姓名原文>")` 前 12 碼（同公司同一人可串；⛔ 不含姓名，見「隱私處理」） |
| method_raw | 預定轉讓方式原文；同一申報多種方式時以「\|」連接（例 `一般交易\|盤後定價交易`） |
| method | 正規化方式（見下表）；多種方式以「+」連接（例 `general+afterhours`） |
| shares | 轉讓股數（多種方式時為合計）。⚠ **只有交易類方式（一般、鉅額、盤後、拍賣）有值**；贈與、信託、洽特定人、私募、過額配售官方此欄空白 ⇒ 用 `plan_own`＋`plan_trust` |
| shares_split | 多種方式時各方式股數，「\|」連接、順序同 method_raw；單一方式時空白 |
| daily_max | 每日於盤中交易最大得轉讓股數（只有一般交易類有值） |
| transferee_type | 受讓人類別：trust_bank／employee_trust／org／individual；官方空白（交易類方式）留空 |
| transferee_org | 受讓人的機構名稱（只有 org、trust_bank 才可能有；只留機構名稱片段，抽不出就空白；多個以「；」連接） |
| hold_own, hold_trust | 目前持有股數：自有持股、保留運用決定權信託股數 |
| plan_own, plan_trust | 預定轉讓總股數：自有、信託 |
| after_own, after_trust | 預定轉讓後持股：自有、信託（⚠ 官方註：會因實際轉讓狀況而不同；實際轉讓要看「事後申報」） |
| valid_period_raw | 有效轉讓期間原文（例 `113/03/30 ~ 113/04/29`） |
| valid_start, valid_end | 有效轉讓期間起迄（西元）；辦理過額配售 1,659 列官方沒有期間 ⇒ 空白 |
| unfinished | 是否申報持股未完成轉讓：「是」或空白 |
| change_note | 異動情形原文（例「本單為變更100/03/25之申報」「已於110/03/22申報變更」）；絕大多數空白 |

## 隱私處理

⛔ 本表放公開 repo ⇒ **不放自然人姓名**。官方原表有申報人姓名、受讓人姓名，處理如下：

- **申報人**：不輸出姓名，改 `holder_key`＝`sha1("<stock_id>|<姓名原文>").hexdigest()[:12]`。同一公司同一申報人（原文完全相同）會得到同一個 key，可串同一人的多筆申報；不同公司的同一人 key 不同。⚠ 雜湊不是加密：知道公司與候選姓名的人可以反推驗證，⛔ 不要再把 key 和姓名對照表放進公開庫。
- **受讓人**：不輸出原文，改兩欄。
  - `transferee_type` 依序判定：含「信託／銀行／商銀」→ `trust_bank`；否則含「限制員工／員工」→ `employee_trust`；否則含法人字樣（股份有限、有限公司、公司、基金會、協會、投資、財團法人、大學、株式會社、LIMITED、LTD、INC、CORP…）→ `org`；其餘非空 → `individual`；空白留空。
  - `transferee_org` 只有 org、trust_bank 才填，而且**只放機構名稱片段**：原文先在「受託／託管／保管／受／括號／破折號／頓號／等」處切段，每段只取到最後一個法人字尾為止（股份有限公司、有限公司、(股)公司、銀行、商銀、證券、大學、株式會社、LTD…）。下面三種段整段丟掉：
    - 沒有法人字尾的段，多半是自然人姓名，例「某某受託信託財產專戶」。
    - 含「公益信託／家族／紀念／律師／會計師／財團法人／社團法人／基金會／文教／基金」的段，這類常以自然人命名。
    - 含同列申報人姓名的段，例「某某一號控股股份有限公司」。
  - 結果：799 列 org／trust_bank 抽不出機構名稱，`transferee_org` 空白；individual、employee_trust 一律空白。
- **role**：只有身分字樣，全量檢查沒有夾帶姓名。程式另有保險：若出現「某某之配偶」，會去掉「之」以前的文字（本次 0 列）。
- **其他欄**：change_note、valid_period_raw 全量檢查，只有日期與固定字樣（「本單為變更…之申報」「已於…申報變更」）。name 是公司名稱。
- ⚠ 已知殘留：少數**公司登記名稱本身含人名**（例「○○○投資股份有限公司」），且不是同列申報人姓名時會保留。這是法人登記名稱，不是自然人欄位。

## 驗收

- ⭐ 144 發每發「解析列數＝頁尾總計」：**全部相符，0 發不符**；每列都是 18 格，0 列解析異常。
- 申報日全部落在該發查詢窗內（0 列越界）⇒ 查詢月份就是依申報日篩。
- 跨發重複 0 列（各發不重疊）；同一發內完全相同的列 121 列（去掉姓名後）（官方本來就重複列出、也算在總計內）⇒ 照官方保留。
- 同一申報（日、代號、姓名、方式、股數、受讓人）跨市場重複出現：0（去姓名前檢查）。
- 隱私檢查：77,466 列逐列比對「該列原始申報人姓名／individual 受讓人姓名」是否出現在任何輸出欄，命中 0（2 列誤報是姓名欄只填了身分字樣「配偶」等）；另隨機抽 20 列人工看過，沒有自然人姓名。
- 交易類列 `shares`＝`plan_own`＋`plan_trust`：有 shares 的 23,076 列中 23,075 相符、1 列不符（1103 2006-06-09，官方原值如此）。
- 2003-05 起每月 `plan_own` 全部 > 0（91/08～92/04 官方股數欄全是 0，故不收）。
- 代號不在公開庫 `origin/main:data/meta/stocks.csv` 的 432 個（sii 92、otc 61、rotc 306）——多為已下市或早年興櫃即撤銷的公司，⛔ 不是代號錯。

## ⚠ 用之前

- ⛔ **可用日＝申報日 `declare_date`**，⛔ 不是有效轉讓期間起日 `valid_start`（用 `valid_end` 或事後申報結果當事件日都會前視）。valid_start 早於申報日的有 5 列（官方原值）。
- ⛔ 這是**事前申報＝「預定」轉讓**，不是實際成交；實際轉讓、未完成部分要另看事後申報（`unfinished＝是` 表示該申報人之後申報了「持股未完成轉讓」）。
- 91/08～92/04（2002-08～2003-04）官方有列但股數全是 0 ⇒ **不收**；本表從 2003-05 起。
- 含已下市公司；興櫃（rotc）早年很多公司之後撤銷登錄，代號在本庫 stocks.csv 查不到。
- 同一人同日可能多列（不同受讓人、不同方式各一列）；要算「家數／人次」請自己依 (stock_id, declare_date, holder_key) 聚合。
- 來源 mopsov 的 robots.txt 為 disallow ⇒ 只在自有排程小量取（每發間隔 ≥ 4 秒）；⛔ 不可改成高頻爬取。
- 新月份：目前是一次性回補，⛔ 還沒接排程；⚠ 程式會整檔覆寫涉及到的年份 ⇒ 補新月份時範圍要涵蓋該年全部月份（例 `--from 115/01 --to 115/10`）。
