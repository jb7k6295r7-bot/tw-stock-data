# ⛔ 讀交易日曆之前先讀這一頁（2026-09-09）

## 這個目錄裡有**三個** coverage 檔，要全部 union 才是完整的交易日曆

```
_coverage.csv           回補檔    backfill.py 寫
_coverage_backfill.csv  舊回補檔  唯讀
_coverage_daily.csv     每日檔    每日管線寫
```

`backfill.py` 的 `coverage_rows()` 三個都讀（舊檔 → 每日檔 → 回補檔，後者覆蓋前者）。
**只讀其中一或兩個，會得到一份看起來完全正常、但停在幾天前的日曆。**

## 這不是假設，2026-09-09 真的發生過

K線線那一側 union 了 `_coverage.csv` 與 `_coverage_backfill.csv` 兩個，
算出「交易日曆最新到 2026-09-03，而價格到 2026-09-08」，於是回報
「日曆缺 09-04、09-07、09-08」。

實際上那三天在 `_coverage_daily.csv` 裡，我方日曆並沒有斷。

⚠ 但這件事的代價不是「他們數字報錯了」，是：
**以日曆為基準的「近 20／60 個交易日不可有缺漏」閘門會靜默往前平移**，
變成看 08-11 ~ 09-03 那個窗——**照跑、照回報通過，而它看的窗裡沒有最近那幾天**。
一檔若 09-04 之後完全沒成交，那個閘門看不到。

## ⇒ 建議的讀法（第一條最穩）

1. **讀 `daily/` 的檔名集合。**
   一天一個檔，**不會分岔**，那是「那一天到底有沒有資料」的唯一事實來源。

   ```python
   import os
   days = sorted(x[:-4] for x in os.listdir("data/universe/daily") if x.endswith(".csv"))
   ```

2. 若要用 `_coverage*`（它多了每個市場的檔數與備註），**三個都要 union**，
   而且⛔ 自己那一側要加一條斷言：**日曆最後一天 ≥ 價格最後一天**。
   少讀一個檔的時候這條會當場紅，而不是安靜地平移。

   我方這一側的同一條斷言在 `calendar_audit.py` 的 `calendar_lag()`，
   每天印進 `data/meta/_last_run.md` 的 `calendar` 區塊（三個檔各自的最後一天都印）。

## ⛔ 為什麼不乾脆合成一個檔

因為三個檔有三個寫入者（每日管線、回補、歷史），合成一個就會變成三支程式搶著整份重寫，
那是另一種更難查的壞法（後推的贏，跟程式新舊無關——`probe.yml` 檔頭記過同一個坑）。
⇒ **保持三個檔，但把「要 union」這件事寫在這裡，而不是只寫在程式裡。**
