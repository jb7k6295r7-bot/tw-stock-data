# 接一條新端點的順序

> 使用者 2026-09-10 定的規矩：
> **「以後新端點第一件事，就是把 `notes`／`hints`／`title` 印出來，再開始比對。」**

⛔ 這一頁不是建議，是**順序**。跳過第 0 步去比對數字，今天已經付過三次代價。

---

## 第 0 步 ⭐ 先把回應**整個**攤開來看，⛔ 不要只看 `fields`／`data`

```python
import backfill as B
raw, err = B.get(url)
d = json.loads(raw)
print("\n".join(B.describe_response(d, want={我送出去的參數})))
```

`describe_response()` 會印出**我方平常丟掉的每一個鍵**，並且順便做兩件對帳。

### 為什麼：我方以前完全沒讀

`_tables()` 只取 `title`／`fields`／`data`，其餘
（`stat`／`date`／`notes`／`hints`／`params`／`total`…）**全部丟掉，而且沒有紀錄**
——連「有這些鍵」都不知道。

### 那些鍵各自能省掉什麼（每一個都對應一件我方**手工做過**的事）

| 鍵 | 它能直接回答的問題 | 我方原本怎麼做 |
|---|---|---|
| `total` | 官方說它給了幾列 | 另外造 N₁、Σamount÷大盤、六張清單差集（67,446 筆） |
| `params` | **我送的參數有沒有生效** | 在三支程式裡各寫一道「回應要講出我請求的那一天」 |
| `notes` | 符號說明／涵蓋起始年／單位 | 用推論，而且**沒有留下出處** |
| `title` | 這一批到底是哪一天／哪一期 | 同上 |

⚠ `params` 那一條最毒也最有用：端點會把收到的參數**回顯**，
而 `TWTAWU` 的 `date=` 就是這樣被看穿的——
送 `date=20150105`，`params` 回 `{date:"20150105", startDate:"20260813", endDate:"20260813"}`
⇒ 它**自己承認**把我的參數換掉了。`describe_response(d, want=…)` 會直接標出來。

## 第 1 步 判斷「回的是不是我要的東西」，⛔ 不是「回了東西沒有」

今天踩到的四種形狀，**每一種都是 `stat:OK`**：

```
① 靜靜回今天       exDailyQ 用 GET／日期不帶斜線；tradingIndex 越界；chtm 越界
② 靜靜回最新一期    MOPS t164sb03 的 year／season 四種組合回應完全相同
③ 回查無資料頁      hist.tpex 的 4,449 bytes（32 個年份「全部命中」）
④ 被 CDN 擋回 HTML  TWSE HTTP 428（只 try/catch JSON 會看成「解析失敗」）
```

⇒ 判準一律是「**這一批要自己講出它是哪一天／哪一期**」，
⛔ 不可以用「檔案夠大」「有回列」「`stat` 是 OK」當判準。

## 第 2 步 兩個方向都比，⛔ 只比一個方向會得到相反的結論

市場情報分析線 2026-09-10 在同一天示範了這個錯與它的代價：

```
09:41  只比「官方有的、我方有沒有」⇒ 宣告「可以直接當回補來源」
09:55  補比反方向 ⇒ 官方少了 17 筆減資 ＋ 5 筆轉上市後的事件
       ⇒ 照 09:41 做會**刪掉減資因子**，那幾檔還原價整段錯
```

## 第 3 步 範圍寫死，⛔ 不要把觀察到的範圍寫成通則

- 「同一族／同一站」不是同一件事：`bulletin/` 家族三支的參數行為**互不相同**
  （`exDailyQ` 無斜線是靜默、`revivt`／`pvChgRslt` 是 `stat:參數錯誤` 大聲失敗）。
- 「我查過的那幾條端點沒有」**不等於**「官方沒有」——
  今天有兩條被推翻（上櫃交易日曆、上櫃除權息歷史），
  兩次都是照**全站選單**找到的，不是照想得到的路徑猜的。
- 單日結論就寫「只有這一天」。

---

## 第 4 步 才輪到寫入

- 先想清楚**誰是這個目錄的唯一寫入者**。換供料是**換維護者**，不是順手加一行。
- 判準檔（`data/meta/`）跟資料（`data/universe/`）分開。
- 長工之前先實測一天，**而且連 push 那條路一起測**（見 `push_data.sh`）。

---

## 第 5 步 ⚠ 量測本身也會說謊：長迴圈要有「這一輪的游標」

市場情報分析線 2026-09-10 12:52 踩到、⭐ 而且差一點回報成資料缺陷：

> **有逾時的執行環境，逾時只殺掉「這一次呼叫」，迴圈還在背景跑。**
> 下一次呼叫又開一個新迴圈、**共用同一個全域游標** ⇒ 少數 id 被處理兩次。

⇒ 他一度把 `3563 2018-06-27` 讀成「我方有重複列」，查原檔才發現**那一天只有一列**。
⛔ **那是量測產生的假象，不是資料缺陷。**

⇒ 兩條做法：
- 游標**綁在這一輪**（區域變數／參數傳遞），⛔ 不要共用全域游標；
- ⭐ 留一個**只會等於、不會超過**的檢核數：正方向的 `hit` 最終**剛好等於**官方筆數
  ⇒ 有 id 被重複處理就會超過。⚠ 沒有這種上界的計數（例如反方向）**要先去重再引用**。
