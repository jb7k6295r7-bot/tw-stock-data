## 五、⭐ 這次學到、值得往下傳的通則

1. **一個轉換（我方代號→外部系統的實際代號）只要有兩個呼叫端，就會有一個漏掉**
   （crypto 的 `_pair()`／USDT 字尾）——跟四點五「同一件事只准一份實作」是同一族，
   ⛔ 這次的代價是一整趟 backfill（8 分鐘）全滅、而且污染了續跑台帳。
2. **「同一天的快照」是一個整體，合併語意要用「同一天整批替換」不是「逐鍵合併」**
   ——逐鍵合併只在「鍵本身就是永久身分」時才對（例如股票代號的歷史股本），
   對「今天的前 15 大是哪幾檔」這種**集合型**快照是錯的語意。
3. **`selftest_no_dup.py` 有兩個偵測盲點**（本輪找到並補上）：
   - `scan()` 的 `MIN_STMTS=3` 門檻讓 2 個 statement 的函式（如 `_get`）永遠躲得過
   - `scan_consts()` 原本只認 `list`／`tuple`，一個 `set` 常數（`STABLECOIN_SYMBOLS`）
     完全繞過去——現在補上 `ast.Set`（排序後比較，因為 set 本身無序）
   ⚠ 這兩個盲點**不是這次才存在**，是這次因為真的踩到才發現——下一個人加新常數／
   新小函式時，不要以為 `selftest_no_dup.py` 綠燈就代表沒有重複。
4. **官方端點的 js 空殼，先試 `<form action=…>`，不要一路挖 js**——這次挖了三層 js
   （inline → 5 支外部檔 → 逐支再挖）才繞到一個無關的全站跑馬燈，而正確答案是
   頁面裡現成的 `<form>` 標籤，一個正規式就找到。`backfill.xhr_clues()` 現在把它
   排在最前面（⓪），比 js 便宜。

## 六、常駐的規矩（⛔ 最容易忘的幾條，沿用自上一版）

- 寫新檔之前先拿「它要做的那件事」**grep 一次 repo**（四點五第七次）。
- 新斷言要用 `mutate.py` 證明**會紅也會綠**；⚠ 「沒抓到」要先排除「突變沒套上去」
  與「baseline 本來就是紅的」；`mutate.py` 對含有 shell 特殊字元（引號、正規式）的
  錨點常常因為 bash 轉義失敗而報「突變沒套上去」——這種情況改用 Edit 工具手動
  停用／還原來驗證，效果相同，不必跟轉義奮鬥。
- 累積型的檔一律**合併不是取代**——⛔ 而「合併」的正確粒度要先想清楚
  （見「五、2」，逐鍵合併不是唯一正確答案）。
- 派工前先確認沒有同 concurrency group 的東西還在跑；派工後**三件都要驗**
  （job conclusion／後果／runlog 時戳），不是看 run 的 status。
- 信件歸檔：✅ 我是唯一收件線且已答覆／會同信簽收全 ✔ 才移走；
  ⛔ 還有人 ✖ 的只簽我自己那一格。
