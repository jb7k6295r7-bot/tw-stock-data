### ⛔⛔ 這次交接新增一條坑：本機可能有一個「跟遠端分支同名」的過期本地分支

這次 push 連續兩次報 `non-fast-forward`，而 `git fetch`／`git ls-remote` 都顯示
遠端 tip 是我本地 commit 的**祖先**（邏輯上該是合法的 fast-forward）。
⇒ 病根：本機除了工作分支 `feature` 之外，還有一個**字面上叫
`claude/financial-market-analysis-mmm5kf`** 的本地分支（落後 33 個 commit）。
`git push origin claude/financial-market-analysis-mmm5kf` 這個寫法，git 會去找
**同名的本地分支**當來源（不是「當前分支推到這個遠端名字」），於是推的其實是
那個過期分支，當然是 non-fast-forward。

⇒ 已刪掉那個過期分支（`git branch -D claude/financial-market-analysis-mmm5kf`）。
⭐ **判準**：push 一直報 non-fast-forward、但 `git merge-base HEAD origin/<branch>`
跟 `git ls-remote` 都顯示是祖先關係時，先 `git branch -vv` 查有沒有同名本地分支，
⛔ 不要照抄舊 handover 的指令重跑好幾次（那樣只會一直失敗，因為錯的是來源 ref
不是網路狀態）。⇒ 之後一律用**顯式 refspec** `feature:claude/financial-market-analysis-mmm5kf`，
不要用裸分支名。

## 六、常駐的規矩（⛔ 最容易忘的幾條，沿用自上一版 ＋ 這次新增一條）

- 寫新檔之前先拿「它要做的那件事」**grep 一次 repo**（四點五第七次）。
- 新斷言要用 `mutate.py` 證明**會紅也會綠**；⚠ 「沒抓到」要先排除「突變沒套上去」
  與「baseline 本來就是紅的」。
- 累積型的檔一律**合併不是取代**——而「合併」的正確粒度要先想清楚
  （逐鍵合併不是唯一正確答案，「同一天的快照」要整批替換）。
- 派工前先確認沒有同 concurrency group 的東西還在跑；派工後**三件都要驗**
  （job conclusion／後果／runlog 時戳），不是看 run 的 status。
- 信件歸檔：✅ 我是唯一收件線且已答覆／會同信簽收全 ✔ 才移走；
  ⛔ 還有人 ✖ 的只簽我自己那一格。
- ⭐⭐ **新增**：push 報 non-fast-forward 但 `merge-base`／`ls-remote` 都顯示是
  合法祖先關係時，先 `git branch -vv` 查有沒有跟遠端分支**同名的過期本地分支**
  ——裸分支名的 `git push origin <name>` 找的是同名本地分支當來源，不是「目前
  這個分支推到那個遠端名字」。一律用顯式 refspec。
