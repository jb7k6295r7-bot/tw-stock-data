## 四、引擎：既有 pick 能不能直接用（⛔ 本件沒改引擎）

既有 `pick="欄名"`（research11.simulate_mtm）：`key = cand[pick]`，NaN → −∞，`order = argsort(−key, kind="stable")`。
- ✗ 同分照候選列的順序（訊號表的列序）排，⛔ 不是抽籤。
- ✗ 走這條路時完全不呼叫 rng ⇒ 不是「同顆種子 rng 接著抽」。
- ✓ 鍵可以放成 sig 的欄位（K0～K4 已算好在 pre_keys.csv）。

建議改法（待裁定收下再改；預設關閉、既有路徑逐位元不變）：新參數 `pick_tie="rng"`，只在 pick 給了時有效：
```python
perm = rng.permutation(len(cand))                      # 與抽籤版同一次抽（抽的次數逐日相同）
order = perm[np.argsort(-key[perm], kind="stable")]    # 依鍵遞減；同分者照這次抽籤的先後
```
- 這正是本件 pre 用的診斷包裝 `RankRng` 的規則。本件沒動引擎，是把 rng 換成包裝物件（引擎只在這一處用 rng），讀呼叫端的 cand 來排；這只是診斷手段，⛔ 不拿來跑判定。
- 引擎改好後的閘：
  - (a) 引擎 `pick=K*, pick_tie="rng"` 的買進清單 ＝ 本件 RankRng 的 200 顆 × 5 鍵，逐筆相同；
  - (b) 常數鍵（全同分）＋ pick_tie ＝ 抽籤版逐位元相同（鑑別：證明同分真的交給同一次抽籤）；
  - (c) pick_tie 不給 ⇒ 既有 pick（relvol）路徑逐位元不變；
  - (d) 其餘既有回歸閘照舊。
