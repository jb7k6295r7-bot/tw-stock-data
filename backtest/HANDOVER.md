      ⛔ 兩者在讀信的人眼裡一模一樣

   ⇒ ✅ 落地兩條：

      ・草稿與送出版不同時，⛔ 不可只說「我改過了」⇒ 一律逐行列出差異

## 五、⭐ 跑一件登錄的實際流程

```
① 收信 → 拿到登錄【全文】→ 驗 sha → 落地 backtest/PREREG<件>.md
② 讀 §判準／§對照組／§必報 ⇒ 寫執行端 backtest/research<件>.py
   ⭐ 四點五：同一件事只准一份實作 ⇒ 引擎走 P14._sim、判準走 P14.judge、
     CI 走 P8.month_ci、持有 n 根走 D.exit_pos（⛔ 不寫裸算式）
   ⛔ 手算 fixture 排在【讀任何資料之前】⇒ 壞了要當場知道
③ 寫自測 t_<件>，⭐ 每一條新斷言都要【證明它會紅】
   ⛔ 突變前後都 `rm -rf __pycache__`（.pyc 只看 mtime＋大小 ⇒ 同尺寸突變會被當成 fresh）
   ⛔ 判紅是 `rc != 0` 或有 ✗，⛔ 不是只數 ✗（崩潰吐 traceback，不印 ✗）
   ⛔ 未套用的突變要 exit 9 ⇒ ⭐ 不可能把「沒套用」讀成綠
④ 小規模冒煙 → 全量跑 → ⭐【再跑一趟】比輸出檔逐位元相同（決定性本身是一道檢查）
⑤ 出報告 → 發信 → ⭐ 下載回來驗送出版
⑥ 記 PROGRESS.md
```
